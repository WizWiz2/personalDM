# Review общности правил из fix/playtest-2026-10-12

Self-review по просьбе владельца: каждое новое ограничение проверяется четырьмя
вопросами — какой общий инвариант мира защищаем; в каких ситуациях оно
ошибочно; может ли оно уничтожить корректную информацию; есть ли негативные
тесты, где похожее обязано остаться разным. Негативные сценарии закреплены
в `tests/test_playtest_rules_generality_gaps.py` со статусом `xfail`: они
описывают желаемое поведение, которого текущие правила ещё не дают.

Вердикт ветки: **не мержить как есть.** Часть правил переживает review, часть
требует переноса ответственности на семантических владельцев (taxonomy,
LLM-арбитраж), одно — откатa.

---

## 1. `scene_state`: single-слот на (scene, subject, predicate) — откатить/перенести

- **Инвариант (заявленный):** у наблюдения сцены одно актуальное значение на слот.
- **Где ошибочно:** свободнотекстовый subject — это подпись, а не идентичность
  объекта. «кровь / находится / у порога» и «кровь / находится / на лестнице» —
  два корректных факта о двух лужах; правило убивает второй. Тот же корень,
  что у телепорта лодки: подпись ≠ объект.
- **Уничтожает ли инфу:** да, молча (supersede старого значения).
- **Граница:** single законен для слотов с сущностным субъектом и состоянием
  типа «один текущий value» — а кардинальность этих слотов знает
  `MemoryTaxonomyService`, не репозиторий.
- **Решение:** убрать принуждение в `FactRepository`; кардинальность — вотерн
  taxonomy (scribe голосует в её границах, revise чинит через supersede).
  До этой работы — xfail `test_two_puddles_of_the_same_label_stay_active_together`.

## 2. Write-barrier — идея верна, реализация даёт обратную гонку

- **Инвариант:** публикация хода не может компенсироваться из-за параллельной
  записи памяти в fingerprint-строки.
- **Где ошибочно (подтверждено):** CS1 оборачивает барьером весь
  `EntityRegistrar.register_from_turn` — внутри LLM-вызовы (envelope,
  arbitration). Пост-джоб может держать барьер десятки секунд, и ход встанет
  в capture→publish на память. Кроме того сага держит барьер через всю
  наррат-генерацию (75–220 с по плейтесту) — память сериализуется за ход целиком.
- **Уничтожает ли инфу:** нет, но превращает конвейер в последовательный.
- **Куда двигаться (выбор архитектора):**
  A) барьер только вокруг транзакционных границ: все LLM вне, от первой записи
  до commit — внутри (у регистрарера нужен явный split на read/plan и durable
  фазы);
  B) снять гонку толерантностью: `assert_unchanged` классифицирует diff — если
  за окно изменилось только то, что пост-джобы имели право изменить
  (presence/позиции, добавленные после capture), публикация принимает новое
  состояние вместо компенсации.
- xfail-тест барьера «память не держит LLM под захватом» требует рефакторинга
  регистрарера, поэтому задокументирован здесь, а не тестом.

## 3. Двойники персон — три винта с разной судьбой

### 3a. Retained-role re-bind (точная строка хранимого роли promoted-персоны) — оставить
- Инвариант: слово в слово тот же роль того же места — тот же человек.
- Ложные срабатывания: новый персонаж с идентичным роль-строкой в той же
  локации → два кандидата → fail-closed конфликт (уже покрыто
  `test_round25/…ambiguous` в существующих тестах).
- Информацию не destroys. **Оставить.**

### 3b. Keeper-join (голый role designator → владелец слота) — сузить или убрать
- Ложное срабатывание: «Старший рыбак» прибыл на причал, где один хранитель
  слота → дизайнатор привяжется к хранителю. Род профессии тут не при чём —
  проверка слепá к семантике.
- Кандидат на сужение (структурный, не лексический сигнал): требовать, чтобы
  evidence mention ссылался на это место (лексема названия локации в
  designator/evidence). Спорно (лексика). Иначе — **убрать**, оставив роль
  семантическому арбитру.
- xfail: `test_foreign_role_designator_does_not_hijack_the_keeper`.

### 3c. Инфлект-твин-гейт («Юнда» при живом «Юнд») — **откатить**
- «Макар» vs «Макара» — два легитимных человека. Падежная форма и новое имя
  детерминированно неразличимы без морфологии + контекста; любой детерминизм
  здесь — лотерея идентичности.
- Настоящий владелец задачи — LLM-арбитраж reveal (уже есть канал) плюс, как
  усиление, спейси-лемма как сигнал кандидата, не как вердикт.
- xfail: `test_a_second_person_with_an_adjacent_name_is_a_real_person`.

## 4. Beat tolerance — оставить
- Инвариант: четыре запрета решают публикацию; инициативная реплика — украшение.
- Ложное срабатывание: ни один ban-вердикт не обходится (проверено pinned
  тестом с отклоняющим валидатором). Инфо не теряет: beat матится только при
  честном honored.
- Закреплённый негативный тест: `test_unhonored_beat_gets_one_repair_then_the_typed_fallback`.

## 5. Покрытие действий — диагностика, не фикс (в отчёте названо patch'ем — принята формулировка «наблюдаемость»)
- Реальное усечение живёт выше компилятора (речевой фильтр, extraction cap).
  Следующий шаг — по телеметрии `action_coverage` на новом плейтесте, с
  решением архитектора: второй проход интерпретатора при разрыве
  requested>planned vs явный `unresolved_intent` в ответ мастера.

## 6. Скрипт-гейт — почти, но нужен локально-осознанный allowlist
- Ложное срабатывание: кампания по-китайски/японски или цитаты на языке
  сеттинга — весь текст уйдёт в repair→fallback. Allowlist скриптов должен
  выводиться из канона кампании (язык кампейна + скрипты имён касты), а не из
  жёсткого стоп-листа.
- Мелкий дефект конвейера: при intrusion валидатор не вызывается, и ремонт
  не видит bans-нарушений того же кандидата (один лишний ремонт, fail-closed
  не нарушен) — починить вместе с allowlist.
- xfail: `test_the_novel_may_quote_the_settings_own_script`.

## Метрика вместо «1001 зелёный»

Согласен: зелёный сьют ≠ играбельность. Регресс-пакет «Бриннхольм»
(инварианты, не заученные реплики):

1. сущность с `slot_id` не имеет второго кандидата на тот же слот в сцене;
2. для любой пары (subject, predicate) в scene_state активны ровно те значения,
   которые допускает taxonomy-кардинальность слота;
3. ни один опубликованный текст не содержит скриптов вне allowlist кампании;
4. `action_coverage.requested >= planned` не имеет silent-gap без записи
   `speech_filtered_actions`;
5. ни один ход не компенсирован ошибкой fingerprint за N-часовой игру;
6. все персонифицированные сущности имеют попарно различные identity_keys
   после длинной кампании.
