# ТЗ: UI/UX фиксы PersonalDM (GUI)

**Статус:** draft для реализации  
**Дата:** 2026-09-13  
**База:** живой прогон GUI + кампания «Багхант 13 сен»  
**Цель:** подтянуть UX потока игры до уровня уже сильного визуального языка, без ребренда и без «перерисовать всё».

## 0. Принципы (не ломать)

1. Сохранить dark RPG-тон: почти чёрный фон, тёплый primary (янтарь/бронза), serif в нарративе, sans в UI.
2. Не добавлять новую навигационную модель workspace (Игра / Герой / Мир / Хроника / Галерея / Кампания).
3. Не превращать Session Zero обратно в анкету.
4. Любой empty / error state обязан говорить: *что случилось*, *что делать дальше*, *что не потеряно*.
5. Не выдумывать метрики «на глаз» в копирайте (никаких ложных «обложка появится сразу после SZ», если генерация опциональна).

## UI-01 — Play: fail-state хода (P0)

### Проблема
При failed generation на экране одновременно: баннер ошибки, opening-проза, карточка «НЕ ОБРАБОТАНО», Undo с неочевидной целью. Пользователь не понимает, какой следующий шаг.

### Требование
1. **Одна** зона ошибки над лентой (или sticky под шапкой сцены), `role="alert"`.
2. В зоне:
   - заголовок (человеческий, не SQL);
   - 1–2 строки смысла;
   - primary: **Повторить ход**;
   - secondary: **Убрать неудачный ход**;
   - tertiary/ghost: **Техническая причина** (раскрывашка).
3. Карточка failed user-turn в ленте:
   - визуально secondary (меньше контраста, чем у успешного хода);
   - бейдж «Не обработано»;
   - без отдельной кнопки Undo внутри opening-блока мастера, если fail относится к user-turn.
4. Кнопка «Откатить последний ход мастера» показывается **только** когда откатывается успешный master-turn, не failed user-turn. Для fail — формулировки из п.2.

### Acceptance
- [ ] На failed generation видны ровно 2 основных действия: повторить / убрать.
- [ ] Opening не выглядит «сломанным абзацем» из-за ошибки (ошибка визуально отделена).
- [ ] После «Убрать» fail-карточка исчезает, баннер исчезает, composer активен.
- [ ] После «Повторить» не остаётся двух копий одного user-turn.

## UI-02 — Play: длинная лента (P0)

### Проблема
Кампания быстро становится простынёй; возврат в «сейчас» неудобен.

### Требование
1. Sticky-кнопка / чип **«К последнему ходу»** появляется, когда пользователь проскроллил вверх больше чем на ~1.5 viewport (порог на усмотрение, но поведение стабильное).
2. Автоскролл вниз только:
   - при новом ходе пользователя;
   - при стриминге/завершении ответа мастера;
   - **не** сбивать позицию, если пользователь явно читает историю (детектор: scroll up во время generation).
3. Опционально (можно вторым PR): для ходов старше N (например 20) — свёртка «Показать более ранние ходы».

### Acceptance
- [ ] Из середины истории один клик возвращает к актуальному хвосту ленты.
- [ ] Если пользователь ушёл читать вверх во время generation, страница сама не прыгает вниз до явного действия / завершения + opt-in.

## UI-03 — Empty states: Галерея и Мир (P0)

### Галерея
**Было плохо:** «Обложка появится после нулевой сессии» при `available:false`.

**Надо:**
- Заголовок: «Галерея пока пуста»
- Текст: обложка/портреты/сцены появляются после **успешной** генерации, когда image runtime доступен.
- Если runtime known-not-ready (ComfyUI не запущен / image off): вторая строка со статусом + ссылка/кнопка «Открыть настройки моделей».

### Мир и знания
**Было плохо:** «Пока здесь ничего нет» сразу после opening.

**Надо:**
- «Пока нет записей в этом разделе»
- «Сведения появляются, когда герой что-то узнаёт, встречает или находит. Скрытый канон мастера сюда не попадает.»
- Не подразумевать ошибку загрузки.

### Acceptance
- [ ] Ни один empty state не обещает артефакт, который система не гарантирует.
- [ ] При image runtime down галерея явно говорит про runtime, не про Session Zero.

## UI-04 — Библиотека: удаление кампании (P1)

### Проблема
«Удалить» на одной линии с «Продолжить».

### Требование
1. Primary на карточке: только **Продолжить** (или **Открыть**).
2. Удаление:
   - либо иконка ⋯ / меню «Ещё» → «Удалить…»;
   - либо secondary text-button внизу карточки, визуально слабее, не в одном `btn primary` ряду.
3. Подтверждение — **in-app danger modal** (не `window.confirm`):
   - название кампании;
   - что удалится;
   - Cancel / Delete (danger).

### Acceptance
- [ ] Нельзя одним промахом нажать Удалить вместо Продолжить.
- [ ] Confirm не системный browser dialog.

## UI-05 — Session Zero: состояния и сайдбар (P1)

### Intro
- `in progress`: «До первой сцены» / «Соберём игру разговором» + текущий helper-текст.
- `completed`: «Нулевая сессия завершена» / «Можно начинать приключение» + короткий CTA-текст без «мастер ещё спрашивает».

### Сайдбар превью
1. Не показывать «—» дольше, чем нужно: если поле пустое — секция с muted hint («появится, когда обсудите X»), не ряд пустых лейблов.
2. Лейбл **Сеттинг** только для `setting_name`. Если его нет — показывать **Жанр** отдельным лейблом, не подменять.
3. После первого substantive answer хотя бы одна секция (Мир или Герой) должна отражать draft без ручного refresh.

### Acceptance
- [ ] Completed SZ визуально не выглядит как онбординг «ещё не начали».
- [ ] Жанр никогда не подписан как «Сеттинг».

## UI-06 — Герой и подписи галереи (P1)

### Герой
- «Текущее состояние» не дублирует тексты из «Цели».
- Если после фильтра пусто — секцию не рендерить.
- Цели: один primary (●), остальные ○ — ок, оставить.

### Галерея карточки
- Подпись = имя персонажа / название сцены / «Обложка: {campaign}», не голый тип «Портрет персонажа».
- Тип можно secondary-строкой мельче.

### Acceptance
- [ ] На досье Ирины нет двух одинаковых абзацев в соседних секциях.
- [ ] В галерее с несколькими портретами их можно различить по подписи без открытия лайтбокса.

## UI-07 — Настройки моделей (P1)

### Проблема
«Загружаем конфигурацию…» может висеть вечно при ошибке; статус runtime второстепенен.

### Требование
1. Состояния блока «Модели»:
   - loading;
   - error + **Повторить**;
   - ready (формы).
2. В ready: статус text/image runtime — вверху секции, не только под полями.
3. Если image = local && not running: заметный warning + CTA «Установить / починить» / «Проверить всё».

### Acceptance
- [ ] Ошибка загрузки ≠ вечный loader.
- [ ] Пользователь видит «ComfyUI не запущен» без скролла охоты.

## UI-08 — Play: повтор локации (P2)

### Проблема
Локация дублируется в title сцены, subtitle, sidebar «Сейчас».

### Требование
Выбрать один primary locus:
- Шапка сцены: **название сцены**;
- Подзаголовок: короткая ситуация / «Начало приключения» без полного path, если path = sidebar;
- Sidebar: полный path / «кто здесь».

### Acceptance
- [ ] Полное имя локации не читается трижды глазом подряд на первом экране.

## UI-09 — Модалка создания кампании (P2)

### Требование
- `role="dialog"`, `aria-modal="true"`, labelledby на заголовок;
- Escape закрывает;
- focus в первое поле при открытии;
- focus trap (минимум: Tab не уводит в фон) — желательно.

### Acceptance
- [ ] Escape закрывает; скринридер видит dialog.

## UI-10 — Обложки без 404-flash (P2)

### Требование
Пока cover `available !== true` — сразу fallback-арт, без `<img src=/generated/...>` и console 404.

### Acceptance
- [ ] На библиотеке с unavailable cover нет 404 в network для cover.png.

## 2. Вне скоупа (явно)

- Новый дизайн-системный кит / смена палитры.
- Mobile-first переделка sidebar.
- Иллюстрации ComfyUI «чтобы всегда были».
- Переписывание Narrator/Truth Engine (кроме того, что уже чинит fail UX).

## 3. Порядок внедрения (рекомендуемый)

1. UI-01 + UI-03 (доверие)  
2. UI-02 + UI-08 (читаемость Play)  
3. UI-04 + UI-05 + UI-06 (библиотека / SZ / герой)  
4. UI-07 + UI-09 + UI-10 (настройки / a11y / polish)

## 4. Критерий «готово» для всего пакета

- Новый пользователь проходит: создать кампанию → SZ → opening → 1 ход → Герой/Мир/Галерея без ложных empty и без хаоса на fail.
- Нет системных `confirm` в основном потоке.
- Fail хода всегда даёт понятный next step за ≤3 секунды взгляда.
